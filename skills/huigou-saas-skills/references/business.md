# 业务规则

## 谁负责什么

SaaS 提供商城接入、推广转链、订单同步、返利结算和钱包接口。合作方负责用户登录、页面、后端集成，以及实际转账；订单返回和结算时间受商城回传影响。

| 名称 | 怎么理解 |
| --- | --- |
| 应用（App Key / Secret） | 合作方后端的调用凭证，可访问哪些组织由服务授权决定。 |
| 组织（organizationId） | 商城配置、Team 和业务数据的管理范围。 |
| Team（teamId） | 组织内的成员分组，可设置默认下单人返利比例。 |
| 成员（memberId） | 登录后得到的业务身份，用它查自己的订单、钱包和提现。 |

后端验证登录用户后调用 `login`，OpenID、组织、Team 和成员 ID 均由后端确认，不直接信任前端传值。OpenID 区分大小写；可选 unionid 用于同一微信开放平台跨应用识别，不替代 OpenID。

Token 当前有效期 30 天，程序按响应中的 `expiresIn`（秒）管理期限；到期后重新验证用户并登录。鉴权失败见 [错误处理](errors.md)。

## 返利和钱包

Team 的默认下单人返利比例可设为 `0`～`0.9000`（最多四位小数），未配置时使用组织比例。更新时显式传值；传 `null` 或省略该字段都会清空 Team 配置。Team 名称和启停状态由后台维护。

| `getProfile` 字段 | 含义 |
| --- | --- |
| `money` | 可用余额；退款追回可能导致负数。 |
| `pendingMoney` | 未结算返利，加上处理中提现所占用的本金。不能直接当作待到账收益。 |
| `withdrawalMoney` | 累计成功提现金额。 |

金额以元为单位，用字符串返回；计算时使用十进制定点方式，避免浮点误差。实际返利以订单结算和账单为准，退款可能撤销或追回返利。

订单 `status` 表示下单、付款、收货等进度；`settleStatus` 表示返利是否结清。未知字段返回 `null`，页面显示“暂无”，不要填成 0。

## 收款与提现

账号类型：1 支付宝、2 微信 OpenID、3 银行卡。首个账号默认选中，后续随成功提交的提现申请切换。只能修改姓名和证件号码；更换账号、类型或开户行需重新登记。删除账号后，历史提现仍保留申请时的收款资料。

1. 成员核对可用余额和收款账号，提交金额字符串（最多两位小数，最低金额按服务规则）。
2. 申请成功后状态为 **3 待打款**，并创建打款记录；可用余额被占用，计入待结算。相同成员、账号、金额已有进行中申请时返回 `CONFLICT`。
3. 合作方核对申请和收款快照，人工转账成功后登记 **3 → 5 已打款**；仅增加累计提现，不增加可用余额。决定不打款时登记 **3 → 2 驳回**，释放占用。
4. 登记处理结果必须填写 1～255 字的备注，并留下流转记录。接口本身不会转账。其他原状态报 `CONFLICT`，其他目标状态报 `BAD_USER_INPUT`。

Schema 还保留历史状态 1、4、6、7 的说明，不代表当前接口支持转入这些状态。提现单和打款单的状态码含义不同，按各自字段文档展示。

超时不等于失败。申请、转账或状态登记结果不明时，先查提现、打款和流转记录，结合实际转账凭证核对，再决定下一步；不要直接重试付款。
