# 合作方返利小程序 Demo 交接

本文档随 Demo 仓库维护，记录接入时需要的使用方式、验证步骤和安全约束。启动命令、环境变量示例以根目录 [README](../README.md) 和 `.env.example` 为准；业务范围与接口定义以对接人交付的接入指南及联调目标环境的 GraphQL Schema 为准。联调进度和阻塞事项请与对接人确认。

源码仓库：[saas-demo](https://codeup.aliyun.com/shanjing/huigou/saas-demo)（`master`）；SSH 克隆地址：`git@codeup.aliyun.com:shanjing/huigou/saas-demo.git`。

## 代码与数据流

| 位置 | 作用 |
| --- | --- |
| `miniprogram/pages/index/` | 唯一页面：连接测试身份、解析与选择候选、读取商品详情、转链、查看资金记录。 |
| `backend/server.mjs`、`backend/http.mjs` | 仅监听 `127.0.0.1` 的 Node HTTP 服务；仅开放固定 `/api/*` 路由。 |
| `backend/core.mjs`、`backend/queries.mjs` | 固定测试身份登录、签名、会话内存、输入校验和允许调用的 GraphQL 操作。 |
| `tests/` | 模拟上游的协议及小程序行为测试；不证明真实环境联通。 |

小程序只向本机后端请求。后端用私有 App Key/Secret 和隔离测试 OpenID 调用 application GraphQL `login`，成员 JWT 只保留在后端内存，页面持有随机会话 ID。后续 member GraphQL 请求通过该 JWT 访问；后端重启或会话失效后须重新连接。

钱包页每次先用成员 JWT 刷新 `getProfile`（可用余额、待结算及提现中、累计已提现），再由本机后端以应用签名调用 `listRevenueStatistic` 获取该成员按日（近 30 日）、月或年（近 366 日）的新增预估/已结算订单返利，分页展示有数据的时段。成员 ID 来自本次固定测试身份的登录结果，页面只能指定周期和页码；统计额不是钱包余额。当前成员统计接口没有自购、带货、邀请、任务四类拆分，页面不会伪造。收款账号列表只下发脱敏姓名/账号，证件号及银行扩展信息不返回小程序。

解析分享内容得到候选后，页面最多并发两条 `getPromotionItem` 查询，逐步补齐真实图片、价格、券、可估算返利和店铺；上游失败时仍可选候选。商品详情优先按解析出的 `itemId` 查询，转链仍使用候选的 `itemUrl`。上游没有的字段不补造；返利状态为 `-1` 时不展示响应中的占位金额。订单列表从 `listOrders` 读取商品明细和订单/结算时间；商品与实付缺失时只展示已有的计佣金额，待结算与已结清返利分别标识，无效返利不显示金额。账号登记、修改、删除及提现申请只在本机开关打开时调用 member GraphQL。提现成功会占用可用余额，发起后刷新余额/默认账号；处理方审核、打款不在 Demo 内。

## 接手环境

1. 确认 Node.js >= 20.11、pnpm、微信开发者工具及有授权的测试 AppID；只在隔离测试环境操作，不使用生产客户账号或真实订单。
2. 从隔离环境的授权负责人取得测试服务地址、应用凭证、组织/Team ID、专用测试 OpenID 和已开通联盟的物料；自行在本机用 `.env.example` 创建 `.env`。不要在仓库、文档、截图、议题或命令日志中写入凭证和成员 JWT。
3. 按 [README 的启动步骤](../README.md#启动与最短操作链) 配置测试服务 HTTPS 地址并启动本机后端。`/api/status` 的 `configured: true` 只证明配置格式有效，不代表登录、商品上游或转链可用。默认后端端口为 8787；改端口须同步修改小程序的 `BASE`。
4. 在微信开发者工具导入仓库根目录。仅本地关闭 `project.private.config.json` 中的合法域名校验以访问本机后端；该文件被忽略，不要提交此设置，也不要将后端端口映射公网。真机、体验版及公开部署不属于此 Demo 的验收范围。
5. 确认测试服务、成员、余额均属专用隔离环境，且已获授权，才在 `.env` 中设 `DEMO_ENABLE_FINANCIAL_WRITES=1` 并重启本机服务；默认值为 `0`。HTTPS 与 `configured: true` 不证明隔离，禁用时后端会拒绝所有账号/资金写入。

## 验证顺序

- `pnpm test`：运行离线协议和页面行为测试。测试里的上游响应是模拟数据，不能替代联调验收。
- 在微信开发者工具中打开小程序，点击「连接测试环境」，核对成员资料是否对应授权的测试身份；失败时检查测试服务地址和凭证，不要使用生产账号替代。
- 粘贴获授权的测试物料，解析并选择候选，按需查看商品详情；核对实际返回的图片、价格等信息。商品上游暂不可用时保留真实错误提示，不用假图或硬编码价格绕过。

在联调目标上依次核对 `login → getProfile → parsePromotionMaterial → getPromotionItem`。**只有确认专用隔离联盟账号及测试物料后**才可调用 `createPromotionLink`；核对真实返回的落地链接/口令即可，转链不代表已下单或已产生返利。订单、账单、提现列表须检查真实返回（包括空列表及分页），不能生成假记录填充界面。将每项的测试环境、时间、结果与失败原因反馈给对接人，切勿贴出私有响应或会话 ID。

资金联调须另外核对隔离测试账号列表的脱敏显示、登记/修改/删除、选择账号后提现申请，以及提交后的钱包余额与提现记录。编辑时留空表示不改，清空证件号须明确勾选；账号/开户行换绑须新建后删除旧号。不能手工设默认号，提现使用的账号会自动成为默认。若提现超时或刷新失败，先查提现记录再决定是否重试，避免重复扣款。没有隔离测试余额或授权时，仅验证离线模拟流程，严禁以真实客户余额代替。

## 常见边界与后续

- 详情请求应传商品 ID 或详情页链接，不应把推广短链当作商品 ID。解析成功但商品上游暂不可用时，卡片仍可选择，并会显示“详情暂不可用”；排查上游前不要把失败归因于样式。
- `SESSION_EXPIRED` 时小程序清除本地会话，需要重新连接；`UPSTREAM` 和 `NETWORK` 需分别检查目标 GraphQL SDL/服务配置、网络与商品上游。后端不对外透传私有错误详情。
- 正式集成必须替换固定 OpenID：由合作方可信登录服务认证实际用户。当前后端无公网身份认证或设备鉴权，不可直接部署成共享测试服务或生产服务。
- 目标环境的 GraphQL Schema 与 Demo 请求字段不一致时，请记录字段差异和安全脱敏后的错误提示并联系对接人确认；不要把离线模拟数据当作接口联通结果。
